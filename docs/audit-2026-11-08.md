# 2026-11-08 全面审查报告（v0.8.0 架构切换）

> 范围：代码/文件/接口清理、UI 与设置页交互、首次使用流程、安全、打包与更新安全。
> 方式：3 个只读并行审计 + 主线复查 + 本机实测（设置页 API、AstrBot/SnowLuma 运行态、诊断体检、构建与仓库自检）。

## 一、架构变更（本次提交的核心）

QQ 接入从「内置桥/单一 provider 会话」改为：

```
QQ → SnowLuma（登录层）→ AstrBot（接入 + 插件）→ dsh_bridge 插件 → DSH（每段对话一个会话）→ 回复回 QQ
```

- 新插件 `astrbot-plugins/astrbot_plugin_dsh_bridge`：AstrBot 侧把 `unified_msg_origin` + 文本转给 DSH；
  跳过 AstrBot 默认 LLM，避免双回复；当前人格随消息同步进 DSH 会话。
- DSH 侧新增 `qq-bridge-chat`（按 QQ 会话建/复用会话，挂到已注册的 `agents` 工作区）、
  本地令牌接口 `/dsh-surfcore/v1/qq-bridge/ask`、发现文件 `~/.dsh/surfcore/astrbot/dsh-bridge.json`。
- 自愈：DSH 端口漂移/令牌轮换/SnowLuma 掉线/wsClients 丢失/provider 指向漂移全部自动修复；
  `dsh_bridge` 随包自动安装（`astrbot-plugins/` 已加入 npm files）。
- 旧方案（内置 QQ 桥、provider 路线、AstrBot 直连模型）保留为回退：维护 → 高级。

### 安全（按审计结论逐项）
- **令牌分权**：provider 用 `raw-chat-token`，桥接插件用独立 `bridge-token`；`dsh-bridge.json` 只发桥接令牌（实测 raw 令牌调桥接接口 401）。
- **管理接口 fail-closed**：DSH 鉴权服务缺失时返回 503，不再静默降级成「本机免登录管理面」。
- **插件安装来源限制**：只接受 `https://github.com/...` 或 `用户/仓库` 形式，拒绝任意 http(s) 源（AstrBot 装插件=加载 Python）。
- **日志脱敏**：`/api/logs` 回显前替换已知令牌/Key（SnowLuma token、AstrBot jwt_secret、provider key、本地令牌、`sk-*`）。
- **Python 桥接插件**：baseUrl 必须本机回环、错误只回固定话术（不回吐内部异常/路径）、不再把 QQ 号写进日志。
- **并发上限**：QQ 桥接最多 3 个并发模型回合、队列 20，超出直接提示「忙不过来」。
- **命令注入**：`spawnHidden` 拒绝 CR/LF；platform-hub 的 `shell:true` 调用前校验 `github:user/repo` 与 profile 格式。
- `consoleToken` 不再传给 UI 检查对象；诊断新增「本机凭据目录权限」检查项。
